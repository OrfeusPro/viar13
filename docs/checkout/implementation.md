# Упрощение корзины и правила скидок — Laravel 13

Дата: 2026-10-07. Проект: `G:\OSPanel\home\viar13`.
Источник согласованной логики: Viar, изменения `cab68a45` и `4cf55ce9`.
Перенос адаптирован к текущему runtime; старые контроллеры целиком не заменялись.

## Реализовано

- Email гостя проверяется на сервере, сохраняется без входа и используется для
  купона и формы данных. Существующий аккаунт не авторизуется простым вводом email.
- Купоны применяются гостем через AJAX. Ошибки возле поля; повторное применение
  возвращает `status=duplicate`. Персональные скидки предварительные до проверки
  действительного пользователя при сохранении заказа.
- Все предложения товаров на первом шаге. Размер заменяется с сохранением фото,
  пропорции и ориентации. Предлагается только более дорогой результат после скидки.
- Увеличение: 15% только на стоимость холста; следующий процентный купон считается
  от уже уменьшенной стоимости холста. Допуслуги оплачиваются полностью.
- Дополнительный товар: 30%, без дополнительного купона. Оба старых признака
  рекомендации учитываются; повторная отправка не добавляет ещё один товар.
- HIT/TOP/SUPER DEAL исключены из предложения 30% и обычных купонов; SALE разрешён.
- Подарочная карта действует на товары, включая акционные; одноразовая,
  не покрывает доставку, остаток не сохраняется. Подсказка оформлена отдельным блоком.
- Подтверждение купона, создание заказа и списание одноразового купона проходят
  в одной транзакции с блокировкой строки. Купон сохраняется неактивным для аудита.
  Работа с файлами, письмо и Synvolve выполняются после сохранения транзакции.
  Сохранена существующая обработка ошибок отправки BestEffortMailService.
- Recovery после 24 часов создаёт купон и гостю; recipient_email и уникальный
  recovery_event_key обеспечивают привязку и повторное использование того же события.
  Письмо ставится в очередь после commit.
- Сохранены Laravel 13 inline login, проверка платежного метода, проверка предложения
  на сервере, ограничения существующих FormRequest и загрузка исходников 100 MB.
- Шаблоны рекламных окон убраны со второго шага; Extra Discount скрыт на шагах 2–4.
- Для холста подпись изготовления берётся из `a_production_time.category=canvas`,
  переводится на текущий язык, учитывает `terms_price`; исходный текст сохраняется
  при отсутствии подходящих данных. Повторный вход в корзину с известным email
  проходит напрямую; popup при необходимости заполняется сохранённым адресом.

## Контракты и БД

Существующие адреса/имена маршрутов сохранены:

- `/basket/coupon_use`: код `couponData`, необязательный `email`; успешный JSON
  `finded=1`, `status=applied|duplicate`, `provisional`; ошибка валидации/купона 422.
- `POST /cart/replace-size`: `basket_key`, `new_size`; цена только серверная,
  допускается только рассчитанное предложение; неправильный размер 422.
- Существующие POST endpoints рекомендаций: серверная цена/наличие предложения,
  идемпотентный повтор; неверные данные 422, отсутствующее предложение отклоняется.
- `POST /cart/set_email`: серверная валидация email, сохранение в сессии и redirect.

Миграция `2026_10_05_120000_add_guest_coupon_recovery_identity.php` добавляет в
`coupons` nullable `recipient_email` с индексом и nullable `recovery_event_key`
с уникальным индексом. Существующие купоны не переписывает. Точечный запуск в
текущей локальной БД ответил `Nothing to migrate`: миграция уже учтена.
Файлы группы `checkout_coupon` добавлены для en/ru/lv/lt/pl/de/et/ee.

## Ограничения и следующий шаг

Реальный заказ, регистрация, отправка recovery через cron и оплата в браузере
не выполнялись. Финальное списание и rollback проверены автоматическими тестами
на SQLite, не конкурентными транзакциями production MySQL. Исходная ошибка
CookieYes из-за локального домена и предупреждения сторонних скриптов не относятся
к переносу checkout. Рабочие изменения Filament не затронуты.

Реализация и локальная проверка завершены. Следующий шаг при выпуске: точечная
миграция, импорт только группы checkout_coupon и проверка оплаты в тестовом контуре.
