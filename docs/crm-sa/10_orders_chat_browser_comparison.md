# ADM-FIL-003 — Сравнение всех чатов с оригиналом

Дата: 2026-08-31. Результат: browser audit выполнен, полное соответствие не принято.

## Область и границы проверки

- Открытые авторизованные Chrome вкладки: `https://viarcanvas.loc/admin/orders`
  (Voyager) и `https://viar13.loc/filament/orders` (Filament), только заказ 18451.
- Проверены все четыре чата колонки «Комментарии»: открытие, состав полей,
  переход к ответу, выбор типа клиентской переписки, закрытие/отмена.
- Ни одной отправки, команды бота или отметки прочтения в этом аудите.
  Новые записи в общей БД не создавались; UAT-флаги не включались.
- Данные 18451: клиентских сообщений 0, внутренних 0, художника 0, artwork 0;
  SA — одно ранее созданное тестовое сообщение 140 и две команды 147/148.
- Поэтому не подтверждены браузером: заполненные client/admin/painter потоки,
  изображения и вложения, длинная история/сортировка, смена unread, приход
  нового сообщения, delivery callback, отправка/получение и матрица ролей.
- Дополнительно прочитаны сохранённые legacy Blade/JS/controllers и новая
  реализация. Ниже выводы по коду отделены от наблюдений в браузере.
- Общий CRM-SA inbox вне заказа (`/admin/sa-conversations`) не проверялся:
  это отдельный ADM-FIL-020, а не один из четырёх order chats.

## Наблюдения браузером

1. Клиент: в Voyager поле и «Add a comment» рядом с историей. В Filament
   сначала окно истории, потом «Ответ клиенту». Во время набора контекст
   истории скрыт. Локализация оригинала английская, нового интерфейса русская.
   Выбор «По наброску» на 18451 открывает обязательное «Изображение» без
   вариантов: это тупиковая ветка UI. Аналогичный риск есть для «По картине».
2. Внутренний: оба интерфейса показывают историю и форму одновременно.
   У Filament есть заголовок с номером заказа и явная подпись textarea;
   у Voyager только placeholder «Комментарий», без названия чата в popup.
3. Художник: в обоих интерфейсах общий ответ доступен без назначенного
   художника. Не считать отсутствие вариантов «Набросок/Картина» в новом
   composer потерей: в оригинальном селекте сейчас только «Общий».
   В новом тексте обещано появление сообщения у «назначенного художника»,
   хотя на 18451 он не назначен; формулировку стоит уточнить.
4. SA: в Voyager кнопки Resume/Pause/Handoff видны сверху, текст и чекбокс
   Handoff снизу. У Filament сначала две кнопки перехода, затем textarea либо
   отдельный select команды и «Подтвердить». Набор команд сохранён, доступ
   к ним требует больше переходов.
   Voyager показывает N/A, Filament PAUSED. Read-only DB проверка объясняет:
   `orders.sa_bot_mode` и `orders.sa_conversation_id` = NULL; у отдельного
   `ADM-FIL-UAT-18451` bot_mode = paused. UAT специально не менял order mirror.
   Это разные источники данных, не ошибка CSS.
   Тестовый текст совпадает. Voyager выводит сырой `(uat_suppressed)` без даты,
   т.к. `sent_at` NULL; Filament — «Тест UAT — не отправлено» и `created_at`.
   Новый журнал полезен, но типы и статусы команд в нём пока технические.
   Файлового upload в просмотренных общих composer нет в обеих версиях.

## Расхождения, подтверждённые кодом, а не текущим заполненным browser flow

- **Автообновление SA отсутствует в Filament.** Legacy
  `resources/views/vendor/voyager/partials/orders/bot_scripts.blade.php`
  опрашивает `admin.sa.messages` каждые 5000 мс, добавляя новые ID.
  В новых Filament views/actions нет polling; history перечитывается при
  открытии/действии. Нужен отдельный тест появления нового входящего сообщения
  без закрытия окна. Legacy polling тоже не обновляет статусы уже известных
  ID — это не эталон полноценной синхронизации delivery.
- **Ссылки в клиентском тексте.** Legacy `admin/client_chat.blade.php` делает
  HTTP(S) linkify после escaping; `order-client-messages.blade.php` выводит
  экранированный plain text. Нужны кликабельные безопасные ссылки, без raw HTML.
- **SA без Handoff имеет другую бизнес-логику.** Legacy
  `AdminSaIntegrationController::sendMessage()` передаёт `mode_after_send=active`,
  когда checkbox выключен. Новый `OrderSaCommandService` не отправляет команду
  боту и сохраняет его режим. Это осознанная защитная реализация, но изменение
  поведения необходимо явно согласовать, а не объявлять полным совпадением.
- **Прочтение не тождественно по UI.** Legacy клиент/художник используют click
  по сообщению; новые views дают явное «Отметить прочитанным». В SA новый
  отдельный read-action меняет unread conversation, не delivery status.
  На текущем заказе нет unread для браузерной проверки; атомарность ingress/read
  остаётся открытой задачей. Не возвращать небезопасное смешение read flags.
- **Автор внутреннего чата.** Legacy показывает first_name + email, новый
  `order-chat-history.blade.php` — имя/фамилию, email только fallback.
  Для совпадения вывода и различения менеджеров нужен email рядом с именем.
- **Права внутреннего чата.** Новое `manageAdminChat` целиком требует update,
  включая просмотр; прочие history actions используют view. Отдельно сверить
  ожидаемые права read-only ролей с оригиналом, не менять их без проверки.

## Доступность и визуальные ограничения

- В Filament у открытых форм есть именованный dialog, подписи полей и видимый
  фокус. У Voyager popup не обозначен dialog в DOM snapshot, закрытие называется
  «×», большинство полей имеют только placeholder. Полная keyboard/screen-reader
  приёмка и соответствие WCAG этим аудитом не подтверждены.
- Снимки одного desktop-браузера: длинная история, мобильная ширина, zoom и
  изображения не проверялись. Нельзя принимать весь layout по empty states.
- Вернуть историю рядом с вводом можно средствами Filament без копирования
  оформления Voyager, сохранив permissions, UAT и явные безопасные действия.

## Итог и следующий шаг

Четыре чата доступны, но утверждение «всё работает как в оригинале» неверно.
Сначала вернуть удобный ответ рядом с историей и видимые команды SA, затем
автообновление и кликабельные ссылки. Отдельно согласовать bot mode после
ответа без Handoff и подготовить изолированный populated-UAT на тестовом заказе.
До этих проверок колонка «Комментарии» и ADM-FIL-003 остаются IN PROGRESS.
