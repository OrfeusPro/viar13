# Настройки BREAD

Страница: `/filament/bread-metadata`, меню «Дополнительно → Настройки BREAD».
Доступ: существующие права `browse_admin` и `browse_bread`.

## Что можно менять

- Подпись, тип поля, порядок, обязательность.
- Видимость в списке, просмотре, создании и редактировании; флаг удаления хранится как metadata Voyager.
- JSON-параметры: варианты, вкладки, defaults и настройки существующих компонентов.
- Добавлять описание существующей физической колонки или виртуального поля связи.

Сохранение поля меняет только `data_rows`. Таблицы, физические колонки, модели,
переводы и значения записей не создаются и не изменяются. Для новой колонки
сначала нужна миграция. Для нового раздела используйте «Создать BREAD для таблицы»;
нужна существующая совместимая модель.

Имя сохранённого поля неизменно. JSON должен быть объектом. Проверяются дубли
полей, существование колонок и связей. При параллельном изменении сохранение
отклоняется; нужно открыть поле заново. Секретные поля нельзя показывать
в списке/просмотре или превращать в текст, служебные поля нельзя редактировать.

## Примеры JSON

Выпадающий список (`select_dropdown`):

```json
{"options":{"1":"Да","0":"Нет"},"default":"0","tab_title":"Основное"}
```

Связь `belongsTo`:

```json
{"type":"belongsTo","table":"users","column":"author_id","key":"id","label":"email"}
```

Связь `belongsToMany`:

```json
{"type":"belongsToMany","table":"users","pivot_table":"page_user","label":"email"}
```

В этом примере нужны `page_user.page_id`, `page_user.user_id` и `users.id`.
Названия ключей выводятся из таблиц по текущему контракту BREAD. Эта связь
доступна в редактировании; создание с many-to-many пока не поддерживается.
Другие типы связей редактор не принимает.

## Ограничения

Специальные страницы (заказы, SEO, клиенты и другие) могут иметь собственные
поля и подписи поверх metadata. Флаг `delete` не заменяет права удаления
записи. `hidden` исключает поле из общей формы, это не скрытый input для записи.
Существующие нестандартные типы сохраняются в выборе, но смена типа не переносит
и не преобразует старые значения. Формат данных должен соответствовать новому
компоненту; такое изменение сначала проверяется локально на копии данных.

## Общие настройки раздела — ADM-AUD-06B

Кнопка «Настройки раздела»: название одной записи/раздела, slug, иконка,
описание, колонка и направление сортировки, колонка поиска, локальный scope.
Сохраняет `data_types` и связанные ссылки `menu_items`, без изменения
бизнес-записей или схемы. Старые прямые ссылки после смены slug не перенаправляются.
В меню обновляются route вида `voyager.<slug>.<action>` и относительные
URL `/admin/<slug>` с сохранением query strings; абсолютные URL не переписываются.

Название раздела используется в общем списке, singular — в редакторе записи,
описание — под заголовком. Иконка BREAD применяется, когда у пункта меню нет
собственной иконки; название и иконка самого пункта меню имеют приоритет.
Сортировка/поиск/scope применяются в общем BREAD-списке, отдельные страницы
заказов/SEO/клиентов имеют собственные запросы.

Допустимы физические колонки, кроме секретных. Без колонки сортировки используется
ID DESC; при равных значениях — ID DESC для стабильной пагинации. Без выбранной
колонки поиска сохраняется поиск по первым четырём видимым текстовым полям.
Выбранная колонка поиска может не отображаться в списке. Scopes берутся из
публичных методов существующей модели без обязательных дополнительных параметров;
служебные withTranslation/withTranslations исключены. Переводы значений продолжают
обрабатываться существующим механизмом BREAD.

Model/controller/policy показаны только для информации; произвольные классы
и разрешения редактор не подключает. `order_display_column`, неизвестные details,
server_side и generate_permissions сохраняются без изменения; UI reorder,
генерация разрешений и редактирование классов не входят в ADM-AUD-06B.

Проверки: весь VoyagerBreadTest — 73 tests / 711 assertions PASS до финальной
правки singular/scopes; после неё targeted settings — 2 tests / 29 assertions PASS.
Проверены сортировка, выбранный поиск, scope, заголовки/описание, сохранность
details/model/data_rows/business records, menu slug updates, invalid/duplicate
slug, неверные колонки/scope, stale edits и отзыв прав. PHP lint и diff-check PASS.
Chrome: Gallery Holsts → настройки → просмотр → Отмена, без сохранения.

## Создание раздела — ADM-AUD-06C

«Создать BREAD для таблицы» показывает физические таблицы текущей схемы БД,
для которых ещё нет `data_types`. После выбора готовит названия, slug и поля
по SQL-структуре. Для каждого поля доступны подпись, тип, порядок, required,
visibility и JSON. Имена/состав физических колонок неизменны.

Выберите существующую модель из `app/Models` для этой таблицы; первичный ключ
должен быть единственным `id`. PHP-классы и физические таблицы редактор не создаёт.
Если модели нет, сначала добавьте её в проект. Это проверяется при сохранении.
Значения строк таблицы не изменяются и не преобразуются при выборе типа поля.

Одной транзакцией создаются `data_types`, `data_rows`, по выбору — определения
пяти разрешений BREAD и корневой пункт меню admin с последующим порядком.
Пункт становится видимым только пользователю с существующим `browse_<table>`.
Ролям разрешения не назначаются. Отсутствие admin menu при включённом добавлении,
неправильное поле/JSON, duplicate или изменённая schema откатывают создание.
Можно снять добавление в меню и генерацию разрешений. Настройки сортировки,
поиска и scope редактируются после создания кнопкой «Настройки раздела».

Default types: числовые SQL-типы → number, date → date, timestamp/datetime →
timestamp, text/json → text_area, boolean → checkbox, прочие → text. Это
предварительные значения, которые можно изменить. Служебные колонки не
редактируются в записи; password/remember_token не показываются и по умолчанию
не записываются. Обязательность и типы нужно согласовать с фактическими данными.

Сравнение: Voyager готовит поля также по schema, позволяет вручную вводить
model/controller/policy, имеет server_side switch и настройки списка прямо при
создании. В новом runtime модели выбираются из существующих, серверная пагинация
всегда включена, классы controller/policy здесь не задаются. Создание связей,
drag sorting и дополнительные компоненты остаются следующими этапами.

В legacy `BreadAdded` listener добавление пункта меню зависит от config,
другой listener может автоматически назначить права admin. Это проверено по
`AddBreadMenuItem`/`AddBreadPermission`; новая версия права ролям не назначает.

Проверки SQLite: 3 creation tests + metadata/settings — 11 tests / 114 assertions PASS.
Chrome read-only: обе формы для abandoned_carts2, SQL-типы/имена семи колонок,
отсутствующая модель и сообщение об этом; рабочее создание не выполнялось.

## Единая форма редактирования (2026-10-09)
Ссылка Редактировать BREAD из каталога теперь сразу открывает настройки раздела и таблицу редактируемых полей. Сохранение транзакционное, с защитой от конкурентного изменения строк и схемы; JSON-ошибка отменяет все изменения. Модель/контроллер/политика и флаги генерации разрешений/серверной пагинации показаны только для просмотра. Названия/slug/icon/description/sort/order_display_column/search/scope и поддержанные настройки полей редактируются. Переводы metadata, drag ordering, конструктор связей и полный набор Voyager/VE типов пока не перенесены. Колонки без metadata не добавляются автоматически.

## ADM-AUD-06E — переводы, порядок, новые колонки (2026-10-09)
Языки сверху переводят названия раздела и подписи полей; общие поля остаются видимыми. Все языковые черновики сохраняются вместе. Переводы совместимы с legacy translations: data_types.display_name_singular/display_name_plural, data_rows.display_name. Пустое значение использует базовую подпись. Строки можно перетаскивать или менять Порядок числом. Колонки без data_rows помечены и будут добавлены при Save, schema не меняется.

Кнопка Создать связь готовит belongsTo/belongsToMany. Выбираются существующие model/table/column/key/label/pivot; применение добавляет настройку в черновик. Настроить/Удалить связь работают в том же черновике и сохраняются общим Save; business records не удаляются. hasOne/hasMany и taggable ещё не перенесены.

Generate Permissions создаёт definitions без auto grants; false не удаляет старые permissions. Модель можно выбрать из совместимых существующих моделей. Генерация классов, изменение controller/policy и отключение серверной пагинации ещё недоступны. Полный список Voyager/VE types и специализированный JSON/icon picker ещё TODO. Проверено 83 tests /839 assertions SQLite PASS + Chrome без Save.

## ADM-AUD-06D-CHILD — hasOne/hasMany (2026-10-09)
Конструктор поддерживает hasOne/hasMany: column — внешний ключ дочерней таблицы, key — колонка текущей таблицы, label — подпись дочерней записи. Связанные записи показываются в списке, просмотре и редактировании согласно visibility. В создании доступность появится после сохранения родителя. Как в оригинальном Voyager, эти типы только показывают детей; назначение/отвязка отсутствуют. Запросы учитывают scopes и SoftDeletes дочерней модели. ## ADM-AUD-06G-GROUP — adv_fields_group (2026-10-09)
- Источники: legacy VE AdvFieldsGroupFormField, formfields/adv_fields_group.blade.php, AdvFieldsGroupContentType::handle и VoyagerExtensionBaseController (group read conversion). View использует сохранённый fields envelope, пустое значение — options; вложенные text/number/textarea. Handler пишет options с field.value из request.
- Реализованы metadata type и проверка fields definitions; Fieldset Add/Edit с изолированным state field.values, TextInput/number/Textarea. Пустой родитель получает значения options.fields.*.value. Названия вложенных полей не конфликтуют с колонками родителя.
- JSON сохраняет fields с type/label/value, дополнительные root/field properties и прежние definitions/ключи. Осознанное отличие от старого handler: сохранённые определения не заменяются целиком options, чтобы не терять прежние поля. Изменение схемы группы существующих записей не применяется автоматически; отдельная миграция при необходимости.
- Неизменённое сохранение оставляет исходный JSON byte-for-byte (numeric input scalar normalization учитывается). Malformed/unsupported вложенные types/keys отображаются readonly и исключены из записи. Metadata разрешает text/number/textarea и identifier keys; другие VE типы отсутствуют в этом original view.
- Сервер валидирует полный набор ключей values, запрещает неизвестные/вложенные ячейки; numeric или string limits. Definitions берутся из БД/options, пользовательский payload не заменяет metadata. Ошибка отменяет транзакцию. Browse/Read показывают label/value; translations сохраняют тот же JSON-контракт и черновики при переключении языка.
